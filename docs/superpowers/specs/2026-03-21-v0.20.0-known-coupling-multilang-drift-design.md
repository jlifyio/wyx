# v0.20.0 Design: Known Coupling + Multi-Language Drift

> Based on field feedback debate (2026-03-21) across 3 projects: DenkiOffice (17 specs), WineLevel3 (8 concepts), StockRecommendation (15 concepts). Two parallel 3-agent debates (ADV+ARCH+DA, Opus) evaluated 14 proposals. PM final review affirmed 2 ACCEPT-WITH-MODS, 2 DEFER, 10 REJECT.

## Accepted Changes

### A5: Multi-language drift documentation (~2 lines)

**Source:** StockRecommendation — `exit_reason` enum mismatch between Rust CLI and spec.

**Change:** Add a note to `drift-detection.md` after step 2, documenting that drift detection is language-agnostic and multi-language projects should scope drift checks to include all implementation directories.

**Rationale:** LLM-based drift already handles any language (Claude reads Rust, Python, Go, etc.). The gap is user awareness, not tooling. Documentation fix, not code change.

**File:** `skills/concept/references/drift-detection.md` — ~2 lines after line 9.

### B1: `## known coupling` section standardization (~20 lines, Phase 1)

**Source:** DenkiOffice (`## boundary exceptions` on Cost concept) and WineLevel3 (Auth→Streak direct SQL write). 2/3 projects independently invented the same pattern.

**Changes:**
1. Add `## known coupling` as optional section to Concept Spec Format in `skills/concept/SKILL.md`
2. Add Design Rules note explaining the section's purpose and constraints
3. Add drift calibration rule: documented coupling = Low severity (vs Critical for undocumented)

**Phase 1 constraints:**
- Format and calibration only — NO hook injection (drift-context.sh unchanged)
- Phase 2 condition: 5+ entries across 2+ projects → then add hook extraction

**File:** `skills/concept/SKILL.md` — ~15 lines (format template + Design Rules note)
**File:** `skills/concept/references/drift-detection.md` — ~5 lines (calibration rule)

## Deferred (with conditions)

- **B6: `:::coupling` classDef** → B1 reaches Phase 2
- **B8: Drift trend dashboard** → N=5+ projects OR 2+ developers (lowered from N=10 per PM)

## Strategic Notes

- **Prevention gap**: All 3 projects report forgotten spec updates. No clean solution exists within current hook architecture (PostToolUse rejected for hook fatigue, CI rejected for LLM cost). Revisit if Claude Code adds session-level hook state.
- **Adoption > sophistication**: At N=3 single-developer, feature additions have negative expected value. Next investment direction should be onboarding, not features.
